# Developer documentation

## Setting up from scratch

### Prerequisites

On a Linux VM (Debian recommended):

```sh
sudo apt-get install -y make
# Docker Engine + Compose plugin: https://docs.docker.com/engine/install/debian/
sudo usermod -aG docker $USER   # then log out and back in
```

### Project layout

```
.
├── Makefile                      # entrypoint for every operation
├── secrets/                      # git-ignored, generated by `make`
│   ├── credentials.txt           # WP_ADMIN_PASSWORD=..., WP_USER_PASSWORD=...
│   ├── db_password.txt
│   └── db_root_password.txt
└── srcs/
    ├── .env                      # non-secret configuration
    ├── .env.example              # template for .env
    ├── docker-compose.yml
    └── requirements/
        ├── mariadb/   {Dockerfile, conf/50-server.cnf, tools/init.sh}
        ├── wordpress/ {Dockerfile, conf/www.conf, tools/setup.sh}
        └── nginx/     {Dockerfile, conf/inception.conf.template, tools/entrypoint.sh}
```

### Configuration files

1. **`srcs/.env`**: copy it from the template and edit it:
   ```sh
   cp srcs/.env.example srcs/.env
   ```
   | Variable | Used by | Meaning |
   |---|---|---|
   | `LOGIN` | Makefile, compose | Your login. Volumes live in `/home/$LOGIN/data` |
   | `DOMAIN_NAME` | nginx, wordpress | `<login>.42.fr` |
   | `VM_IP` | Makefile (`make hosts`) | IP the domain maps to in `/etc/hosts`; empty means `127.0.0.1` |
   | `MYSQL_DATABASE`, `MYSQL_USER` | mariadb, wordpress | Database name and application user |
   | `WP_TITLE` | wordpress | Site title |
   | `WP_ADMIN_USER`, `WP_ADMIN_EMAIL` | wordpress | Administrator (the name must **not** contain "admin"; `setup.sh` rejects it) |
   | `WP_USER`, `WP_USER_EMAIL` | wordpress | Second user, with the author role |

2. **`secrets/`**: created automatically by `make secrets` (called by `make`) with random values. You can also write them by hand beforehand. Existing files are never overwritten.

3. **Domain**: `make hosts` appends `<VM_IP or 127.0.0.1> <login>.42.fr` to `/etc/hosts` on the machine where you run it. If the domain is already listed, it does nothing, so edit `/etc/hosts` by hand when the IP changes.

## Building and launching

```sh
make        # = dirs + secrets + docker compose up -d --build
```

What happens:

1. `make dirs` creates `/home/$LOGIN/data/{mariadb,wordpress}`.
2. `make secrets` generates any missing secret files.
3. Compose builds the three images (`mariadb:inception`, `wordpress:inception`, `nginx:inception`) and starts them in this order:
   - **mariadb**: `init.sh` runs `mariadb-install-db` on an empty volume, then bootstraps the root password, database and user, and finally `exec mariadbd`.
   - **wordpress** (after mariadb is *healthy*): `setup.sh` waits for the database, installs WordPress with WP-CLI if `wp-config.php` is missing, creates both users, then `exec php-fpm8.2 -F`.
   - **nginx**: `entrypoint.sh` generates a self-signed certificate, renders the server block with `DOMAIN_NAME`, then `exec nginx -g 'daemon off;'`.

The Makefile always calls `docker compose -f srcs/docker-compose.yml -p inception`, so you can run it from the root.

## Managing containers and volumes

| Makefile | Plain Docker equivalent |
|---|---|
| `make ps` | `docker compose -f srcs/docker-compose.yml ps` |
| `make logs` | `docker compose -f srcs/docker-compose.yml logs -f` |
| `make down` | stop and remove the containers and network (volumes are kept) |
| `make clean` | `down` + `docker system prune -af` |
| `make fclean` | `down -v --rmi all`, prune, and `sudo rm -rf /home/$LOGIN/data` |
| `make re` | `fclean` + `all` |

Useful commands while developing:

```sh
docker exec -it mariadb mariadb -u root -p"$(cat secrets/db_root_password.txt)"   # SQL shell
docker exec -it wordpress wp --allow-root user list                               # WP-CLI
docker exec -it nginx nginx -t                                                    # validate nginx config
docker compose -f srcs/docker-compose.yml up -d --build nginx                     # rebuild one service
docker volume ls && docker volume inspect wordpress_data
docker network inspect inception
```

After changing a Dockerfile or a file in `conf/` or `tools/`, run `make` again. Compose only rebuilds what changed.

## Where the data lives and how it persists

| Volume | Mounted in | Stored on host |
|---|---|---|
| `mariadb_data` | mariadb: `/var/lib/mysql` | `/home/$LOGIN/data/mariadb` |
| `wordpress_data` | wordpress, nginx: `/var/www/html` | `/home/$LOGIN/data/wordpress` |

Both are **named volumes** (`driver: local` with `driver_opts: type: none, o: bind, device: ...`). Docker manages them by name, while their contents are written to the required host folder.

- Data persists across `make stop`, `make down`, container crashes and VM reboots.
- The entrypoint scripts are idempotent. They skip setup when `/var/lib/mysql/$MYSQL_DATABASE` or `wp-config.php` already exists, so existing content is never overwritten.
- To start over completely, use `make fclean` (or `make re`), which deletes the volumes and the host folders.
- Values in `.env` and `secrets/` are only applied at first initialisation. After changing them, run `make re`.
